# ELM327 + macOS: Bluetooth, порты, права

Проверено на macOS (MBP). Драйвер подключения — `mycar/connection.py`; диагностика — `python -m mycar doctor`.

## 1. Варианты адаптера

| Вариант | Подключение | Порт для `--port` |
|---|---|---|
| **Bluetooth Classic** ELM327 (v1.5) | сопряжение в Системных настройках → устройство появляется как `/dev/cu.ELM327-…` (или похожее `tty.*` имя) | `/dev/cu.ELM327-XXXX` |
| **USB** ELM327 (FTDI/CH340) | просто воткнуть; нужен драйвер (для CH340: `brew install --cask wch-ch34x-usb-driver`) | `/dev/cu.usbserial-…` |
| **Wi-Fi** ELM327 | подключить Mac к Wi-Fi сети адаптера | `socket://<ip-адаптера>:35000` (TCP) |

macOS не создаёт outgoing SPP `/dev`-узел автоматически для всех BT-донглов; если после сопряжения устройство не появилось — см. раздел 3 и запасные варианты (USB/Wi-Fi самые безболезненные).

## 2. Права Bluetooth для Python (то, о чём ты спрашивал)

Да — macOS требует разрешения, если процесс работает с Bluetooth (CoreBluetooth / сопряжение из скрипта):

1. Первый запуск `python -m mycar capture` из терминала → всплывёт диалог
   *«"Terminal" (или iTerm2 / VS Code) хочет использовать Bluetooth»* → **Allow / Разрешить**.
2. Если диалога не было или отказали: **Системные настройки → Конфиденциальность и безопасность → Bluetooth** → добавить своё терминальное приложение (Terminal / iTerm2 / VS Code) и включить тумблер.
3. После изменения прав перезапустить терминал.
4. Для venv — разрешение выдаётся терминальному приложению, а не самому `python` (правило macOS: запрашивает «responsible process»).

## 3. Порядок первого подключения (актуально, проверено на живом адаптере 2026-11-23)

**BT-клон «ELM327 v1.5» (двухрановый) — работает только через BLE:**

1. Вставить донгл в DLC3 (NGX10), зажигание ON.
2. Сопряжение в macOS **не нужно**. Закрыть CarScanner на iPhone (клон держит одного клиента — iPhone может молча перехватить донгл при подаче питания).
3. Запустить `python -m mycar capture` — драйвер сам найдёт адаптер по BLE (сервис `0000fff0`), инициализирует и начнёт сессию с дашбордом.
4. Если донгл «молчит» — перевтыкнуть питание (клоны зависают после жёстких kill и SSP-манипуляций). Останов сессии — только `Ctrl+C`.
5. Классическое SPP-сопряжение (System Settings → Pair, пин 1234/0000) для этого клона делать **не надо** — SPP-профиль у него на macOS сломан, а касание SPP вешает донгл. USB/Wi-Fi-адаптеры работают как раньше (см. ниже).

Для USB/Wi-Fi адаптеров (порядок не менялся):

1. Вставить адаптер; USB появится как `/dev/cu.usbserial-*`.
2. `python -m mycar doctor` → порты и подсказки.
3. `python -m mycar capture` (USB — авто; Wi-Fi: `--port socket://<ip>:35000`, Mac должен быть в Wi-Fi сети самого адаптера).

## 4. Типичные проблемы

| Симптом | Причина / решение |
|---|---|
| BLE-адаптер не находится сканом | донгл занят iPhone (закрыть CarScanner), только что перевтыкнут (подождать 10 с), или висит после SPP-коннекта (перевтыкнуть питание) |
| Сессия рвётся через ~30 с | норма для клона: capture сам переподключается и продолжает запись; вмешательство не нужно |
| «No OBD serial port found» (USB/Wi-Fi) | не спарено/не в сети адаптера — смотри `ls /dev/cu.*`, передай явно `--port` |
| Порт есть, но «car does not answer» | зажигание не включено (нужно IGN ON — два нажатия START без тормоза) |
| Ответы рвутся / таймауты (USB) | дешёвые флакующие донглы; попробуй USB-вариант получше |
| Кастомный Toyota PID (`21 82`) пустой | у BLE-клона прошивка не меняет TX-заголовок (ATSH — заглушка): физическая адресация невозможна, температура CVT нечитаема. Нужен адаптер с честным ATSH; код готов. Доказательства: `mycar/AGENT.md` |

## 5. Безопасность

- Логи пишутся только на чтение (Mode 01) — ничего не записывает в ЭБУ.
- Во время сессии зажигание ON, двигатель работает; не оставляй донгл в разъёме на стоянке (садит АКБ — донглы спят не всегда корректно).
