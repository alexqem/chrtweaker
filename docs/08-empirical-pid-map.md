# 08 · Реальная карта PID Toyota C-HR NGX10 (эмпирический свип, 2026-11-24)

Снято живьём: `logs/sweep_*.txt` (Mode-01 00..FF + Mode 09 raw), `logs/extras_*.txt`
(Mode 22 «в лоб», Mode 09 цепочка, скан Mode 06). Инструмент: `python -m mycar probe --sweep`.

**Главный факт: битмаски поддержки врут.** `0100…` рекламируют 20 PID, реально отвечают **52**
(например, `0x5C` масло не advertised, но жив). Единственный честный способ карты — спрашивать
все 256. Наоборот тоже бывает: `0x0B`/`0x23` иногда числятся, но молчат — верить только ответам.

### Живые, но недекодированные (сырьё сохранено)

`0x3E (0C 80)`, `0x43 (00 33)`, `0x44 (80 13)`, `0x47 (78)`, `0x49 (28)`, `0x4A (51)`,
`0x4C (28)`, `0x6D (03 02 D9 02 DC …)`, `0x70 (03 0C 8F 0C 8B …)`, `0x72 (01 3E …)`,
`0x77 (01 55 …)`, `0x87 (01 04 70 …)`, `0x9D (00 05 00 05)`, `0xA6 (00 0C 39 98)*`.
В Car Scanner 2.2.52 этих PID нет — расшифровка эмпирическая (TODO).
\* ответ `41 A6` пришёл с опозданием на запросе `01AA` — единственный сбой атрибуции в свипе.

### Мёртвые (проверено — NO DATA)

- **`0x0B` MAP** — boost по OBD не получить (в карточках дашборда больше нет).
- **`0x23` rail_p (ТНВД D-4T)** — давление рампы не получить.
- **`0xB4` ATF/CVT (Mode-01 расширение Toyota)** — не отвечает.
- **K-line расширения OBD2K** (`0x1B2/0x1B3/0x1E4/0x1E7/0x1E8/0x1F4/0x1F7/0x1F8/0x1F9/0x1FE`) —
  в свипе молчат (ожидаемо: профиль KWP 1998–2008).

## Mode 09 (идентичность)

| Запрос | 7E8 (ECM) | 7E9 (TCM) |
|---|---|---|
| 0900 маска | `55 40` → 02, 04, 06, 08, 0A | `14 40` → 04, 06, 0A |
| 0902 VIN | `NGX10-2017682` + паддинг пробелами до 17 (JDM chassis number) | — (не поддерживает) |
| 0904 CalID | `896631041000` | `896651034000` |
| 0906 CVN | `19AF7D3D` | `AC6C2B7B` |
| 0908 | счётчики In-Use Performance (20×2 байт, raw) | — |
| 090A имя | `ECM-EngineControl` | `TCM-TransmisCtrl` |

- `0920`/`0940` — NO DATA (цепочка масок кончается на `0900`).
- Парсинг — через **пересборку ISO-TP по ЭБУ** (`toyota.assemble_ecu`): два ЭБУ отвечают
  на `0904`/`0906`/`090A` и ELM перемежает их кадры; без разбора по заголовкам CalID
  резался до «896» (так и было в первой версии).
- CalID `8966…` — формат Toyota (89663-xxxxx / 89665-xxxxx). Для гипотезы «JDM-калибровка»
  (docs/06) это и есть идентификатор прошивки; CVN — контрольная сумма.

## Mode 06 (результаты мониторингов) — работает!

Скан `0601…06FF` (пропуская кратные 0x20, как в Car Scanner) дал **8 ответов**:
`0601, 0602, 0621, 0635, 06A1, 06A2, 06A4, 06A5` (все от 7E8, multi-frame).
Формат записи из Car Scanner: `[MID][TID][UASID][VAL hi][VAL lo][MIN][MAX]` (9 байт,
UASID: 1=raw, 2=÷10, 3=÷100, 4=÷1000; pass = MIN ≤ VAL ≤ MAX).
Сырые ответы — в `logs/extras_*.txt`. Расшифровка MID/TID для Toyota в каталоге
отсутствует (там только generic-имена) — сопоставление эмпирическое (TODO).

## Mode 22 «в лоб» (последняя надежда на CVT) — закрыто

`221627/221628/221622/22162A/22162B/221626/221015` отправлены без заголовка (уходят на
7DF) — **все NO DATA**. Полная картина путей к температуре CVT из реверса Car Scanner:

| Путь | Заголовок | Итог |
|---|---|---|
| `01B4` (Mode 01) | любой / 7DF | ❌ NO DATA |
| `21D9`/`2182` (Mode 21) | 7DF-вариант | ❌ NO DATA |
| `221627/221628` (UDS) | `700`/`701` (физ.) | ❌ функционально NO DATA; физически недоступны (ATSH-заглушка) |
| Mode 06 (TID мониторов) | 7DF | ⚠ ответы есть, но нужна эмпирическая карта TID |

**Вывод: без адаптера с настоящим ATSH температура CVT на этой машине недоступна.** Это
ограничение железа. Кандидаты декода (`toyota._atf_variants`) сохранены на случай смены
адаптера.

## Как это повторить

```sh
.venv/bin/python -m mycar probe --sweep     # карта 00..FF + Mode 09 raw (~2 мин)
```
