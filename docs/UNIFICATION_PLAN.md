# План объединения документации, веб-интерфейса и Android-приложения

Цель: устранить ручной перенос данных и рассинхронизацию между Python (`mycar/`), веб-дашбордом (`dashboard.html`) и Android (`android/`), сохранив единый источник истины.

## 1. Единые схемы данных (`shared/` или `android/app/src/main/assets/`)

| Артефакт | Сейчас | Целевое состояние |
|---|---|---|
| Профили и нормы | `assets/profiles.json` (уже общий) | Добавить `extended_probes` (какие ECU/PID зондировать для профиля) |
| ECU-твики | `assets/tweaks.json` (уже общий, RU+EN) | Добавить `group` / `applies_to` (какие профили поддерживают твик) |
| Стандартные и расширенные PID | Разделены между `mycar/sensors.py` и `Sensors.kt` | Вынести в `assets/pids.json` (`pid`, `name`, `bytes`, `scale`, `offset`, `unit`, `ecu`) |

## 2. Единый UI-контракт (Веб ↔ Android)

1. **Карточки и графики по возможностям авто (Capability-driven UI):**
   - Оба клиента скрывают карточку/график, если датчик не ответил в сессии (`oil_temp`, `cvt_temp`, `catalyst`, `7D2` HV, `700` misfires).
   - Лог зондирования (`ECU Probe Log`) пишется в едином формате `[capability] ECU:PID -> OK/SILENT`.
2. **Switch-твики:**
   - При подключении оба клиента вызывают `read_all_switches` (`21xx`), выставляют реальное положение `ON/OFF` и делают неподдерживаемые пункты неактивными (серыми).
3. **Словари локализации:**
   - Веб-дашборд может загружать `strings` / переводы из общего JSON-словаря или `/api/i18n`, вместо дублирования русских/английских подписей в `dashboard.html`.

## 3. Объединение документации (`docs/` + `README.md`)

1. **`README.md`** — только точка входа: установка APK, однострочный запуск на macOS/Linux, таблица совместимости профилей и ссылки на `docs/`.
2. **`docs/PROTOCOLS_AND_PIDS.md`** — объединить справочники по Mode 01/06/09, CVT (`01B4`/`21D9`/`2182`/`221627`) и расширенным ECU (`0x750`, `0x7C0`, `0x7C4`, `0x700`, `0x7D2`).
3. **`docs/ECU_TWEAKS.md`** — генерировать или сверять таблицу твиков напрямую из `tweaks.json` в CI-тесте, чтобы документация не расходилась с кодом.

## 4. Автоматическая проверка синхронности (CI)

- В `tests/test_profiles_and_tweaks.py` и `EcuTweaksTest.kt` проверять паритет количества профилей, твиков и PID из общих JSON-файлов.
- При добавлении нового профиля/PID/твика достаточно отредактировать один JSON-файл — Python, веб-дашборд и Android подхватят его автоматически.
